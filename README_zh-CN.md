# ⚓ 港口大师 2 · React + TypeScript 版

> 🌐 **双语文档** | [🇬🇧 View English](README.md)

这是港口大师 2 的一次彻底重制。原先的 Python 服务端加单文件 HTML 前端，被完整改写成了一个类型完备的 Node 后端和一个 React 前端。游戏内容、规则玩法、双语界面都和原作一模一样，只是把当初的两个巨型文件，整理成了一个清爽的 monorepo。

---

## 📖 1. 游戏简介

欢迎回到海上丝绸之路。两到五位船长共同经营同一段航程，始终停留在同一回合、同一阶段。你们既要比拼声望，也会在途中互通有无，交换货物、金币和情报。从航海家的罗盘里抽取一项福缘，向牙行购买密语，给旗舰加装模块，并在每段航程里都为工资、维护费和税款留足现金（轻松 8 回合、标准 12 回合、高难 16 回合）。声望最高的船长获胜。

这一版保留了原作的全部内容，只更换了底层引擎：

- 🧩 **一个游戏，两个应用，一份共享核心。** Node 的 WebSocket 服务端掌握全部权威游戏逻辑，React 前端负责渲染。两端都引用同一份 `packages/shared` 里的数据表和协议类型，因此永远不会各执一词。
- 🔤 **全程 TypeScript**，从难度阶梯到互市防刷校验，都开启了严格的编译选项。
- 🧪 **一套真正的测试。** 348 个测试覆盖了各项公式、阶段状态机、密码哈希、大厅、协议分发，以及一次完整的 Socket 往返流程，跑完大约一秒。
- 🌍 **英文（默认）与简体中文**，每个界面都能用 🌐 按钮随时切换，登录页和大厅页也不例外。
- 👑 **皇命金单。** 航程行进到特定节点时，贸易阶段会落下一张钦定贡令，抵得上好几张普通订单，全程最后一张还会被特别标记出来。
- 🎯 **定向互市订单。** 既可以公开发给全房间，也可以只发给某一位船长，这时只有对方看得到、也只有对方能接受。这条规则由服务端强制执行，而不只是界面上藏起来。
- 🪶 **文件小而清晰。** 原作是两个很大的文件，一个 Python 服务端和一个 HTML 页面。同一款游戏在这里被拆成 154 个职责单一的源文件，每个都对应原作的某一处，另有 36 个文件装着测试。
- 🛡️ **能守住形状的护栏。** 严格模式的 TypeScript、开启了 React Hooks 规则的 ESLint，以及 Prettier，都会跑遍整个仓库，那类只会在对局中途才暴露出来的错误，就在敲代码的时候被拦下了。

如果你从没玩过，这一版的玩法和港口大师 2 完全一致。下文既讲怎么运行，也讲怎么游玩。

## 🛠️ 2. 安装与运行

### ✅ 前置要求

- 主机上需要 **Node.js 20.19 及以上，或 22.12 及以上**（Vite 构建需要较新的运行时）。
- **npm**（随 Node 一同安装）。
- Windows、macOS 或 Linux 均可。玩家本人只需要一个现代浏览器。

### 🚀 快速上手（单端口，适合分享）

正式游玩，以及通过互联网分享，都推荐这种方式。

```bash
npm install        # 一次性安装所有工作区
npm run serve      # 先构建前端，再用单一端口托管整个游戏
```

在浏览器里打开 `http://localhost:8080`，注册账号并登录。网页和 WebSocket 共用同一个端口，所以一条隧道就能带起整个游戏：

```bash
ngrok http 8080
```

把 ngrok 给出的地址发给朋友即可。https 与 wss 的适配是自动完成的，无需任何额外配置。

### 🧑‍💻 开发模式（热更新，双端口）

改代码时通常希望有热更新，于是前端和后端分开运行。开两个终端：

```bash
npm run dev:server   # Node 后端跑在 :8080，改动后自动重启
npm run dev:client   # Vite 开发服务器跑在 :5173，模块热替换
```

打开 `http://localhost:5173`。Vite 会把 `/ws` 这条 WebSocket 转发给后端，所以浏览器始终只对着一个地址。

### 🎯 两个浏览器，一局游戏

港口大师 2 可容纳 2 到 5 位船长，至少需要两个已登录的会话才能离开登录页。请用两个不同的浏览器，或者一个普通窗口加一个无痕窗口，各自注册一个账号。

### ☁️ 部署到线上

临时开一局的话，上面的单端口构建加一条隧道就够了。想让它长期在线，这个项目按两块来托管：

- **服务端**放在能维持长驻进程的平台上，比如 Railway。仓库根目录的 `railway.json` 已经写好了构建和启动命令。有两个变量要注意：`PORT` 由平台设置、服务端自己读取；`USERS_FILE_PATH` 应指向挂载卷上的文件，这样账号才能在重新部署后保留下来。
- **客户端**是一份静态产物，任何能托管静态文件的地方都可以，Vercel 也在其列。用 `VITE_WS_URL` 把它指向服务端，例如 `wss://yourapp.up.railway.app/ws`。不设置的话，客户端会认为 WebSocket 就在自己所在的域名下，而这只有单端口构建才成立。
- 当客户端搬到另一个域名之后，用服务端的 `ALLOWED_ORIGINS` 限制谁可以建立连接。

[`DEPLOYMENT_GUIDE.md`](DEPLOYMENT_GUIDE.md) 完整记录了这套架构的一次真实部署，连走过的弯路都写了进去，第一次部署之前值得先读一遍。

## 🗂️ 3. 项目结构

整个项目是一个 npm workspaces 的 monorepo，三个包各司其职：

```
.
├── packages/shared/      # 两端共享的唯一事实来源
│   └── src/
│       ├── data/         # 游戏数据表：配方、价格、工资、福缘、
│       │                 # 模块、季风、港口、难度阶梯……
│       ├── domain/       # 核心类型：工人、互市订单、密语线索、卡牌……
│       └── protocol/     # 通信协议：PlayerGameState、各类消息
│
├── apps/server/          # 权威的 Node 游戏服务端（无界面）
│   ├── src/
│   │   ├── game/         # PlayerGame 及其委托的纯函数规则
│   │   │                 # （成本、生产、海盗、模块、发牌）
│   │   ├── session/      # SharedSession，共享阶段状态机
│   │   ├── actions/      # 每个游戏内动作一个处理函数（采购、互市、雇佣……）
│   │   ├── lobby/        # 在线名册、邀请、聊天
│   │   ├── auth/         # PBKDF2 密码哈希、用户存储
│   │   ├── ws/           # WebSocket 连接循环与消息路由
│   │   ├── http/         # 为构建后的前端做静态文件服务
│   │   └── main.ts       # 把一切串起来的入口
│   ├── tests/            # 277 个 vitest 测试，目录结构与 src/ 对应
│   └── data/users.json   # 账号存储（运行时创建和更新）
│
└── apps/client/          # React 前端（Vite）
    ├── src/
    │   ├── i18n/         # 双语层：所有文案、手册正文、
    │   │                 # 服务端日志翻译表、物品名称……
    │   ├── ws/           # 唯一的 WebSocket 钩子
    │   ├── state/        # 会话、提示、观战上下文，以及把服务端
    │   │                 # 消息翻译成状态的协议分发层
    │   ├── components/   # 布局、登录、大厅、各面板、各阶段界面，
    │   │                 # 以及弹窗、手册、聊天、提示气泡、观战等系统
    │   └── styles/       # 全局样式表
    └── tests/            # 71 个 vitest 测试，不需要浏览器
```

核心原则是：凡是两端必须保持一致的东西，都放在 `packages/shared` 里被引用，而绝不复制。这是防止前后端在某个价格或某条规则上产生分歧的主要手段。

## 🎮 4. 游戏机制

轻松 **8 段航程**（回合），标准 **12 段**，高难 **16 段**，每段航程都要经过 **8 个阶段**。任何阶段都要等所有船长都确认后才会推进。

| 阶段        | 内容                                                                           |
| :---------- | :----------------------------------------------------------------------------- |
| **⚓ 启航** | 确认开始本回合。从第 2 回合起，这一页还会回顾上一回合的结算。                  |
| **🧭 福缘** | 罗盘随机给你发出若干福缘，每位船长拿到的都不同。锁定其中一项，只在本回合生效。 |
| **🛒 采购** | 从补给卡里购买原料和成品。牙行密语面板就在最上方，出售关于未来需求的情报。     |
| **🤝 互市** | 与房间内其他船长交易。发布一条「我出某物换某物」的提案，任意一方接受即刻成交。 |
| **👥 工匠** | 雇佣或解雇工匠，并分配生产任务。材料会立即扣除。                               |
| **📦 贸易** | 用库存交付港口订单。你买到的线索会在这里兑现成带 🗣️ 标记的稳定订单。           |
| **🔧 结算** | 产出自动入库、工资自动支付，然后你要付 15 金币的船队维护费。付不起就破产。     |
| **🚢 船坞** | 想升级就升级商船（0 到 3 级），抽取模块，然后结束本段航程。                    |

### ⚖️ 难度模式

每局都从 **轻松** 开始。发出邀请或开设房间的船长挑选难度，受邀者看过说明并同意后才开局，因此所有船长始终在同一难度下航行。

- **轻松（8 回合）** 让整段航程都停留在基础货物之内：三种原料、四种入门成品、前三类工匠，以及与之配套的福缘、模块、港口和天象。市场永远不会过度拥挤，是从容上手的好起点。
- **标准（12 回合）** 以更紧凑的节奏开放完整贸易，丝路特许在第 4、8 回合分批解锁，但不会出现暗通海盗的牙行。
- **高难（16 回合）** 是开启了可疑牙行机制的完整挑战，在第 6、10 回合分批解锁。需要打理的事务多得多，对舱位和金币的争夺也激烈许多。

### 📦 原料与成品

你先购入原料，由工匠加工成成品，再用成品交付订单。成品的价值远高于原料，所以「低买、加工、高卖」这个循环才是利润所在。商品在其特产港口更便宜，价格也会随天象浮动。

### 🧭 福缘

每回合航海家的罗盘都会给你单独发一手 4 张随机增益，你锁定其中一项，只在本回合有效。效果从直接给金币，到运费减半、雇佣更便宜、额外多一张订单，或免费获得一条牙行密语线索，不一而足。

### 🔧 船舶模块

升级商船即可解锁模块槽位（每级一个，最多 3 个）。每个船坞阶段，你都可以抽出固定的一批三个模块并安装其中一个，从走私暗舱到超载引擎都有。每回合还能把这一批换一次。

### 💰 税收与财务

成品订单大约缴 5% 的增值税，每回合结束时再按本回合净利润缴约 10% 的所得税（持「免税令」福缘时为 5%）。无论赚没赚到钱，工资和 15 金币的维护费每回合都得付，所以现金流永远是第一位的。运费随订单件数上升，随船级、福缘和已装模块下降；具体金额由服务端算好，贸易界面显示的就是它，看到多少就是扣多少。

### 🌐 联机机制

账号采用加盐的 PBKDF2 哈希存储。大厅会列出谁在线，邀请会带上所选难度，每分钟一次的冷却让节奏不至于太乱；也可以开设一个 2 到 5 人的房间，让其他船长自由加入。登录成功后浏览器里会留下一个凭证，所以刷新页面或稍后回来都能直接回到自己的航程，不用重新输密码，同一个账号也只能同时在一处登录。点右侧同行名单里的任意一位船长，就能打开一个实时窗口看他的船队，谈交易前先摸清对方缺什么很方便；破产的船长也用同一个窗口看完整段航程。只有所有船长都离线并超过一段宽限时间，航程才会被回收。

## 💡 6. 策略建议

- **现金流压倒一切。** 工资加维护费每回合都要付，付不起的后果远比少赚一点严重得多。左侧面板会实时核算你本回合应付的款项，时刻盯着它。
- **卖成品，别卖原料。** 一个香囊的价值远高于做它所用的材料。
- **购买密语。** 每条线索都会在本回合后段兑现成稳定订单，所以提前备货就能稳赚；装上牙行网络模块还能让密语更便宜。
- **留意天象。** 季风每两个回合换一次，会抬高某些港口的报酬、压低某些采购价，也会带动海盗风险一起变。房间里所有人吹的是同一阵风，所以值得按两回合一组来安排。
- **多和其他船长沟通。** 你们能看到彼此的货物和金币，所以善用互市阶段和聊天，互相补缺。

## 🏆 7. 游戏终局与评级

当最后一段航程结算完毕，你的声望（每笔已交付订单的净利润累计）会换来一个商人评级。由于航程越长赚得越多，每个难度都有各自的门槛。最高的 **丝绸之路霸主** 评级要求声望达到 **轻松 1200 以上**、**标准 3000 以上**、**高难 6000 以上**。破产的船长依然可以打开观战窗口，看着其他船长走完航程；等所有船长都结束后，任意一位都能重新起航。

## 🛡️ 8. 故障排除

- **运行脚本时报 `Cannot find module ... .bin/...`。** 某些云同步工具会把 `node_modules/.bin` 里的符号链接压成普通文件。用 `rm -rf node_modules/.bin && npm install` 重建即可；如果反复出现，就把代码放到同步目录之外。
- **页面能打开但没有样式。** 确认你是通过 `npm run dev:client` 启动，或用 `npm run build` 构建过前端。样式表由 Vite 打包，直接打开裸文件是加载不到的。
- **过不了登录页。** 这至少需要两个账号。打开第二个浏览器或无痕窗口，再注册一位船长。
- **服务端重启过。** 账号会留在 `apps/server/data/users.json` 里，但正在进行的航程存在内存中，重启即丢失，请重开一局。
- **想通过互联网分享。** 用单端口构建（`npm run serve`），再把那一个端口隧道出去（`ngrok http 8080`），让网页和 WebSocket 共用同一个 https 来源。
- **托管的前端连不上服务端。** 当前后端分处不同域名时，前端需要用 `VITE_WS_URL` 指向服务端的 `wss://…/ws` 地址，而且它是在构建时写进产物里的，改了要重新构建，光重启没用。
- **部署之后账号没了。** 平台重建了容器并清空了文件系统。挂一个卷，再把 `USERS_FILE_PATH` 指向卷上的文件。

## 🌟 快速参考

- **运行**：先 `npm install`，再 `npm run serve`，然后打开 `http://localhost:8080`。
- **分享**：`ngrok http 8080`；想正式托管就用 `railway.json` 配合 [`DEPLOYMENT_GUIDE.md`](DEPLOYMENT_GUIDE.md)。

- **获胜条件**：拿到最高的霸主评级，即轻松 1200 以上、标准 3000 以上、或高难 6000 以上的声望。
